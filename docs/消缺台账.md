### D1（P1、已修于第 40 轮）声明名位置与关键字/类型别名的同词冲突

- **修复记录（第 40 轮）**：translate() 第 2 步查表改绑句法位置：a. 前一词元映射值∈{const,var,fn}（含 ASCII 直通形）时当前词强制转码；b. 母语词已被工程 intern 为标识符时，除 `:` 右侧类型标注位外引用处标识符优先；点分别名链（标准库→std）在第 1 步先行、不受影响。回归：translate.zig 新测试（声明/引用/类型三面全等词）+ 探针 `常数 文本 = 嵌入文件("note.txt")` run EXIT=0。
- **残留面→转 D1b。**

- **复现**：`常数 文本 = 嵌入文件("note.txt");` → 生成 `const []const u8 = @embedFile("note.txt");`（非法 Zig，
  报 `expected 'identifier', found '['`）。同根面：`变量 整数 = 5;`、`函数 文本() void {}` 等一切"声明名恰为词表词"。
- **根因**：`translate()` 对 `nonascii_word` 的处置顺序是 别名链→关键字/类型表→转码，第 2 步查表**不绑定句法位置**；
  声明关键字（映射值为 `const`/`var`/`fn` 等）之后紧跟的词元在句法上是"被声明的名字"，应走第 3 步转码而非第 2 步查表。
- **修复方向**：词元级句法角色判定——前一词元映射值 ∈ {const, var, fn}（含 `公开`/`函数` 组合的尾词元）时，
  当前 `nonascii_word` 强制按标识符 intern。须同步检查所有"词后跟名"的位置（struct 字段名、枚举成员名等）。
- **回归**：`常数 文本 = …` 生成 `const z_N = @embedFile(…)` 且 run EXIT=0；既有 demo 类型别名面（`变量 数量: 整数`）不回退。
- **注**：第 29 轮测过"超串标识符整词避让"（`整数倍` 不拆），但**全等撞词**从未覆盖，属测试矩阵空洞。

- **复现**（第 47 轮诊断族广扫实测坐实）：（a）`常数 甲 = 1;`（未使用）的提示尾部拖着一段开发者维护备注“（与 `unused local variable` 分属不同措辞，需单独登记。）”——含英文 zig 消息名与“登记/措辞”等元词；`成员函数不存在` 同形泄漏“（与 `no field named`、`has no member` 分属不同消息）”。（b）切片/数组/元组成员访问笔误（`s.lenn`）产 `no member named 'lenn' in '[]const u8'`、ASCII 内建笔误（`@importt`）产 `invalid builtin function: '@importt'`——两族无对应词条，整句英文透传。
- **根因**：（a）写包时把“为何单独登记此条”的设计理由直接附在提示里，本应只留在文档；既有守卫只查方言侧键纯中文（R3），不查提示正文。（b）既有 `成员不存在 = has no member` 与实际消息 `no member named …` 措辞不同、不命中；`invalid builtin` 从未收录。
- **修复（第 47 轮）**：① 删除两条提示尾部的括号元注释；②新增两词条 `成员名不存在 = no member named`、`未知内建函数 = invalid builtin function`（均置于 `no member named 'main'` 条目之后，按首个子串命中原则保留入口专用优先，不遮挡）；③新增守卫测试（translate.zig）：“诊断译文/提示”逐条断言——不含元注释关键词黑名单（登记/备注/措辞/需单独/分属/历史上/曾经/TODO/FIXME/维护者），且剥去反引号包裹后无 ≥3 连续 ASCII 字母词组成的英文句。
- **回归**：端到端探针 `s.lenn`→`所访问的成员在该类型上不存在`、`@importt`→`引用了不存在的内建函数（@ 开头）`、`s.world()`→`成员或成员函数不存在`（提示已无元注释尾巴）均全中文本地化；全量 92/92（新增 1 守卫测）；demos 4/4。

## 设计边界（有意不做）

## 结构性风险（写包/改码守则）
