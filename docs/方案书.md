# zzc 方案书：用母语编写真实 Zig

## 目标

让母语者用**自己的语言的关键字与标识符**编写程序，而底层是**真实、可编译、可 fmt、可 eject 毕业**的标准 Zig。不是玩具语言、不是子集，而是 Zig 的一层可逆词法方言。

## 核心原则

1. **只替换词法单元，不改变语法结构。** `()` `{}` `[]` `!T` `?T` `@import` `\\` 多行字符串、注释等全部保留 ASCII Zig 原生写法。方言与标准 Zig 逐 token 同构，因此任意时刻都能无损翻译回 Zig。
2. **输出的是真实 Zig。** 翻译结果通过官方 `zig fmt --check`；`zzc build/run/test` 本质是「翻译 → 调用本机 `zig`」。
3. **标识符自动转码。** 母语变量/函数名经工程级符号表映射为稳定 ASCII 名 `z_<n>`，跨文件、跨会话一致；`eject` 时母语原名以注释保留。
4. **引擎语言无关，语言包是数据。** 关键字表、类型别名、标准库路径、报错模式与教学提示全部在语言包文件里。新增方言 = 新增一份包文件（见 [contributing-lang-pack.md](contributing-lang-pack.md)）。

## 数据流

```
母语源码 (src/main.zz)
   │  zzc 词法扫描 + 逐 token 翻译
   ▼
标准 Zig (.zzc/gen/main.zig) + 位置映射 ColumnMap
   │  进程调用本机 zig 0.17
   ▼
真实编译：exe / 英文报错
   │  解析报错 → ColumnMap 回译 → 语言包教学提示
   ▼
母语报错 + 母语行列号 + 「下一步该做什么」

zzc eject ──▶ 标准 Zig 工程 + build.zig(+zon) + 符号对照注释 ──▶ 纯 zig build 独立构建
```

## 模块划分

| 模块 | 职责 |
|---|---|
| `src/main.zig` | CLI 入口与子命令（init/check/build/run/test/eject/lang/version）、zig 进程调用、`.zzc/` 缓存 |
| `transpiler/lexer.zig` | Zig 词法边界识别（字符串/字符/多行串/注释/`@"..."`/`@builtin`），保护不需翻译的内容 |
| `transpiler/keyword.zig`（语言包驱动）| 关键字与类型别名翻译，由语言包 comptime 载入的哈希表提供 |
| `transpiler/mangle.zig` | 母语标识符 ↔ ASCII `z_<n>` 双向符号表 |
| `transpiler/column_map.zig` | 方言偏移 ↔ 标准偏移双向映射，行列换算 |
| `transpiler/translate.zig` | 翻译主引擎：别名链贪心匹配 → 关键字表 → 标识符转码；空白逐字节复制、CRLF 归一 LF |
| `lang/pack.zig` | 行式语言包解析（`keywords`/`aliases`/`diagnostics` 三段）|
| `diag/parse.zig`＋`diag/translate.zig` | 解析 zig stderr 的 `path:line:col: kind: msg`、`note:`、`referenced by:`，回译成母语并附提示 |
| `diag/fullwidth.zig` | 全角标点与同形异体字符检测，翻译阶段即拦截 |

## 关键设计决策

- **位置映射按字节偏移、先在生成区定位再反查。** 方言源码含多字节 CJK 且可能是 CRLF，生成源码是纯 ASCII 且 LF；行号因逐字节保留换行而两端一致，但行内字节宽度不同，故回译时先在标准源码里把 zig 的列换算成字节偏移，再经 ColumnMap 反查方言偏移，得到母语行列。
- **翻译输出丢弃 `\r`。** 真实 Zig 与 `zig fmt` 以 LF 为规范，翻译时统一 CRLF→LF，保证产物 fmt-clean。
- **标准库路径用点分链贪心最长匹配。** `标准库.打印` 优先于 `标准库`，未命中的段回退（`标准库→std`，其余原样透传），使表能小而覆盖高频。
- **eject 的 `build.zig.zon` fingerprint 由工具链探测。** Zig 0.17 的 `zig build` 要求 zon 含顶层 `fingerprint`，其高 32 位由包名派生、不可自行伪造。`eject` 先写一份不带 fingerprint 的 zon，跑一次 `zig build` 读取其「suggested value」，回写后再验证毕业构建，从而始终产出合法的独立工程。
- **CLI 失败静默退出。** 方言用户不应看到 zzc 自身的 Zig 错误返回跟踪；失败路径先刷出已缓冲的母语报错再 `process.exit`。

## 毕业路径（eject）

`zzc eject [目录]` 把整个方言工程翻译成标准 Zig：
- 每个 `.zz` → `.zig`，文件头附「母语符号对照表」注释；
- 生成 `build.zig`（预配 root module / 目标 / 优化选项）与 `build.zig.zon`（含探测到的 fingerprint、`minimum_zig_version`）；
- 当场 `zig build` 验证，退出即代表「此后纯 Zig 工具链可独立维护」。

## 边界与取舍

- 不支持「改变语序的自然语言语法」——只做词法替换，保证与 Zig 同构、可逆。
- 标识符转码用位置编号，不引入拼音库；后续可迭代为拼音/英文语义名。
- 工具链通过进程调用 `zig`，不链接 libzig，避免与具体 zig 版本强绑定。
