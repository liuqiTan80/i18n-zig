## 一、代码架构分析

### 1.1 模块划分评估

#### 当前模块结构
```
src/
├── main.zig              # CLI入口（约320行）
├── root.zig              # 核心模块门面（约22行）
├── cli/
│   └── args.zig          # CLI参数解析（约263行）
├── lang/
│   └── pack.zig          # 语言包解析（约115行）
├── transpiler/
│   ├── lexer.zig         # 词法扫描器（约223行）
│   ├── translate.zig     # 翻译引擎（约375行）
│   ├── mangle.zig        # 符号转码（约278行）
│   └── column_map.zig    # 位置映射（约99行）
└── diag/
    ├── translate.zig     # 报错回译（约328行）
    └── fullwidth.zig     # 全角拦截（约343行）
```

#### 模块划分合理性评估

| 模块 | 行数 | 职责单一性 | 内聚性 | 耦合度 | 评分 |
|------|------|-----------|--------|--------|------|
| main.zig | 320 | 中 | 中 | 高 | ⭐⭐⭐ |
| root.zig | 22 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| cli/args.zig | 263 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| lang/pack.zig | 115 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| transpiler/lexer.zig | 223 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| transpiler/translate.zig | 375 | 中 | 中 | 中 | ⭐⭐⭐ |
| transpiler/mangle.zig | 278 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| transpiler/column_map.zig | 99 | 高 | 高 | 低 | ⭐⭐⭐⭐⭐ |
| diag/translate.zig | 328 | 中 | 中 | 中 | ⭐⭐⭐ |
| diag/fullwidth.zig | 343 | 中 | 中 | 中 | ⭐⭐⭐ |

**架构优势**：
1. ✅ 模块职责清晰，符合单一职责原则
2. ✅ 核心模块（lexer、mangle、column_map）内聚性高
3. ✅ 门面模式（root.zig）设计合理，便于测试和第三方嵌入
4. ✅ 语言包解析与翻译引擎解耦，支持多语言扩展

**架构风险**：
1. ⚠️ `main.zig` 行数过多（320行），包含业务逻辑与IO操作
2. ⚠️ `translate.zig` 和 `fullwidth.zig` 行数较多，建议拆分
3. ⚠️ 缺少 `loader.zig`、`validator.zig` 等语言包管理模块

### 1.2 模块间依赖关系

#### 依赖图分析
```
main.zig → cli/args.zig
main.zig → transpiler/translate.zig
main.zig → transpiler/mangle.zig
main.zig → transpiler/column_map.zig
main.zig → lang/pack.zig
main.zig → diag/translate.zig

transpiler/translate.zig → transpiler/lexer.zig
transpiler/translate.zig → transpiler/mangle.zig
transpiler/translate.zig → transpiler/column_map.zig
transpiler/translate.zig → lang/pack.zig
transpiler/translate.zig → diag/fullwidth.zig

diag/translate.zig → transpiler/column_map.zig
transpiler/mangle.zig → (无外部依赖)
lang/pack.zig → (无外部依赖)
```

**依赖问题**：
1. ⚠️ `main.zig` 直接依赖所有模块，违反迪米特法则
2. ⚠️ `translate.zig` 依赖 `fullwidth.zig`，形成循环依赖风险
3. ✅ 底层模块（mangle、pack、column_map）无外部依赖，可独立测试

### 1.3 架构可扩展性评估

| 扩展场景 | 支持程度 | 改进建议 |
|----------|----------|----------|
| 新增语言包 | ✅ 良好 | 当前架构支持，无需修改引擎 |
| 新增诊断模式 | ✅ 良好 | 语言包格式支持动态扩展 |
| 新增CLI命令 | ⚠️ 一般 | 需修改 main.zig，建议命令模式 |
| 第三方库翻译 | ⚠️ 一般 | 需实现 translate.zig 的库翻译逻辑 |
| 多语言并行 | ⚠️ 一般 | 需实现语言包注册表机制 |

### 1.4 架构改进建议

1. **拆分 main.zig**：
   - 创建 `cli/command.zig` 处理子命令
   - 创建 `cli/run.zig` 处理 run 命令逻辑
   - 创建 `cli/eject.zig` 处理 eject 命令逻辑

2. **完善语言包管理**：
   - 创建 `lang/loader.zig` 实现运行时加载
   - 创建 `lang/validator.zig` 实现格式验证
   - 创建 `lang/registry.zig` 实现多语言包管理

3. **优化依赖关系**：
   - 引入依赖注入模式，减少 main.zig 的直接依赖
   - 创建 `context.zig` 封装全局状态（gpa、io_等）

## 三、性能分析

### 3.1 关键路径性能瓶颈

#### 性能热点分析

| 函数 | 调用频率 | 时间复杂度 | 瓶颈点 |
|------|----------|------------|--------|
| `lexer.scan` | 每文件1次 | O(n) | 字符串扫描 |
| `translate.translate` | 每文件1次 | O(n×m) | 词元匹配 |
| `mangle.intern` | 每标识符1次 | O(1) | HashMap查找 |
| `ColumnMap.toNative` | 每报错1次 | O(k) | 线性扫描 |
| `fullwidth.check` | 每文件1次 | O(n×c) | 码点迭代 |

**性能瓶颈识别**：
1. ⚠️ `ColumnMap.toNative` 使用线性扫描，k 较大时性能下降
2. ⚠️ `fullwidth.check` 对每个词元进行码点迭代，CJK 文本性能较低
3. ⚠️ `matchDiag` 对每个诊断模式进行子串匹配，模式较多时性能下降

### 3.2 内存使用效率

#### 内存分配分析

| 模块 | 主要分配 | 峰值估算 | 释放策略 |
|------|----------|----------|----------|
| main.zig | 符号表、ColumnMap | ~10MB | 进程级释放 |
| transpiler/lexer.zig | 词元数组 | ~1MB/文件 | 调用方释放 |
| transpiler/translate.zig | 输出字符串 | ~2MB/文件 | 调用方释放 |
| transpiler/mangle.zig | 符号表 | ~5MB | 进程级释放 |
| diag/translate.zig | 回译字符串 | ~0.5MB/报错 | 调用方释放 |

**内存问题**：
1. ⚠️ 使用 `std.ArrayList` 频繁分配，可能产生内存碎片
2. ⚠️ `gpa.dupe` 分配后未复用，每次调用都重新分配
3. ✅ 使用 ArenaAllocator 管理测试内存，避免泄漏

### 3.3 I/O 操作优化空间

#### I/O 操作分析

| 操作 | 频率 | 优化空间 |
|------|------|----------|
| `readWhole` | 每文件1次 | ✅ 已优化，使用 `readFileAlloc` |
| `writeWhole` | 每文件1次 | ⚠️ 可优化，使用缓冲写入 |
| `createDirPath` | 每目录1次 | ✅ 已优化，批量创建 |
| `stageEmbedAssets` | 每资源1次 | ⚠️ 可优化，并行拷贝 |

**I/O 优化建议**：
1. 使用 `std.io.BufferedWriter` 优化写入性能
2. 对小文件使用内存映射（`mmap`）减少系统调用
3. 对资源文件使用并行拷贝提升性能
