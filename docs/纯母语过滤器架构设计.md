# 纯母语过滤器架构设计

**文档版本**: 1.1.0  
**创建日期**: 2026-10-10  
**状态**: 已实现（第 48–52 轮落地）——本文是实现前的设计草案，若干假设与实际落地不同，**差异一律以文末《十、实现对照》为准**  
**优先级**: P0

---

## 一、设计目标

1. **纯母语原则**：任何母语编写的代码，报错信息必须 100% 使用该母语
2. **零英文泄漏**：不允许任何英文错误提示出现在母语报错中
3. **硬性约束优先级**：当性能、功能与纯母语原则冲突时，纯母语原则优先级最高

## 三、核心算法设计

### 3.1 英文检测算法

**目标**：检测文本中的英文残留

**算法**：
```zig
/// 检测文本中是否包含英文残留
/// 返回：true = 有英文残留，false = 无英文残留
pub fn detectEnglish(text: []const u8) bool {
    for (text) |c| {
        if (std.ascii.isAlphabetic(c)) {
            return true;
        }
    }
    return false;
}
```

**优化**：
- 使用正则表达式匹配 ASCII 字母序列
- 支持配置最小匹配长度（默认 3 个字符）
- 支持排除数字和标点符号

### 3.2 白名单机制

**目标**：允许某些英文内容（如标识符、类型名）

**白名单格式**：
```
# 支持正则表达式
^[A-Z][a-zA-Z0-9]*$    # 驼峰命名（如 MyType、MyVariable）
^[a-z_][a-zA-Z0-9_]*$  # 蛇形命名（如 my_variable、_my_var）
^@[a-zA-Z]+$           # Zig 内建函数（如 @import、@memcpy）
^[0-9]+$               # 纯数字
```

**数据结构**：
```zig
pub const Whitelist = struct {
    patterns: std.ArrayList(std.mem.Pattern),

    pub fn init(gpa: std.mem.Allocator) Whitelist {
        return .{ .patterns = std.ArrayList(std.mem.Pattern).init(gpa) };
    }

    pub fn add(self: *Whitelist, pattern: []const u8) !void {
        try self.patterns.append(std.mem.compilePattern(pattern));
    }

    pub fn check(self: Whitelist, text: []const u8) bool {
        for (self.patterns.items) |p| {
            if (p.matches(text)) return true;
        }
        return false;
    }
};
```

### 3.3 兜底翻译策略

**目标**：对于无法回译的英文，提供中文提示

**策略**：
1. **短语替换**：使用 `localizeRunner` 中的短语映射表
2. **通用提示**：生成 "[未翻译] 原文：xxx"
3. **教学提示**：提供中文教学建议

**兜底提示模板**：
```zig
const FALLBACK_MESSAGE = \
    "[未翻译] 此报错暂未提供中文翻译，请参考以下英文原文：\\n" +
    "  原文: {s}\\n" +
    "  建议: 请检查代码语法或查阅 Zig 文档";
```

### 3.4 日志记录机制

**目标**：记录未翻译短语，便于后续补充语言包

**日志格式**：
```json
{
    "timestamp": "2026-10-10T12:00:00Z",
    "phrase": "expected type, found 'i64'",
    "location": "src/main.zz:5:10",
    "suggested_translation": "期望类型，实得 'i64'",
    "status": "pending"
}
```

**输出位置**：
- `docs/消缺台账.md` - 开发阶段记录
- `logs/untranslated_phrases.json` - 运行时记录

## 四、API 设计

### 4.1 核心函数

```zig
pub const PureFilter = struct {
    /// 检测文本中的英文残留
    pub fn detectEnglish(text: []const u8) bool;

    /// 过滤英文残留，返回中文提示
    pub fn filterMessage(
        gpa: std.mem.Allocator,
        text: []const u8,
        whitelist: Whitelist,
    ) ![]const u8;

    /// 添加白名单规则
    pub fn addToWhitelist(filter: *PureFilter, pattern: []const u8) !void;

    /// 记录未翻译短语
    pub fn logUntranslated(
        filter: *PureFilter,
        phrase: []const u8,
        location: []const u8,
    ) !void;

    /// 从配置加载过滤器
    pub fn fromConfig(gpa: std.mem.Allocator, config_path: []const u8) !PureFilter;
};
```

### 4.2 配置结构

```zig
pub const PureFilterConfig = struct {
    enabled: bool = true,
    min_english_length: usize = 3,
    fallback_message: []const u8 = "[未翻译] 此报错暂未提供中文翻译",
    whitelist_patterns: []const []const u8 = &.{
        "^[A-Z][a-zA-Z0-9]*$",
        "^[a-z_][a-zA-Z0-9_]*$",
        "^@[a-zA-Z]+$",
        "^[0-9]+$",
    },
    log_path: []const u8 = "logs/untranslated_phrases.json", // 草案形：现状默认值取 `pub const default_log_path` 单一真值（197 轮 D64），且传非默认值不改落盘点位（见「实现对照」第 8 条）
    strict_mode: bool = false, // true = 严格模式，任何英文都拦截
```

### 5.1 集成到报错回译流程

```zig
const PureFilter = @import("pure_filter.zig");

pub fn renderDiag(...) ![]const u8 {
    // ... 现有逻辑 ...

    // 集成纯母语过滤器
    var owned_filtered: ?[]const u8 = null;
    defer if (owned_filtered) |o| gpa.free(o);

    if (pure_filter.detectEnglish(msg_disp)) {
        if (!pure_filter.whitelist.check(msg_disp)) {
            owned_filtered = try pure_filter.filterMessage(gpa, msg_disp, whitelist);
            msg_disp = owned_filtered.?;
            try pure_filter.logUntranslated(msg_disp, file_path);
        }
    }

}
```

## 十、实现对照（48–52 轮现状）

本节记录设计草案与实际落地的差异，**以下为权威事实**：

1. **白名单不是正则**。草案 3.2/4.2 设想用 `std.mem.compilePattern` 正则——0.17 无此 API，且与「工具层零硬编码」相左。实际：白名单规则由语言包 `[whitelist]` 段以**整行精确匹配**供给（F2）；`PureFilter.applyPackRules` 从包加载，引擎不内置任何驼峰/蛇形/`@`正则。
2. **API 形状不同**。实际入口为 `PureFilter.init(gpa, config, log_list)`与 `filterMessage(gpa, text, location, timestamp_epoch_s) -> ?[]const u8`（非草案的多参 `filterMessage(gpa,text,whitelist)`）；命中兑底时往注入的 `log_list` 记录。人类阅读报告面为 `renderReport(gpa, items)`。
3. **时间戳由调用边界注入（D7）**。`pure_filter` 模块本体不摸 `Io`、保持纯可测；产品时间源由 `diag/translate.zig` 的 `nowEpochS(io_)` 在记录时传入，无产品时间语境（单测图）传 0。
4. **F3 落盘真实实现**。草案只列意向路径；实际用 `std.json.Stringify.valueAlloc` 序列化合法 JSON（禁手写拼接、交 std.json 转义、`escape_unicode` 默认关以保 CJK 直观）落 `logs/untranslated_phrases.json`；进程级清单跨多次 zigCompile 累积；`main` 的 `defer` 与 `bail` 两退出路径都刷盘（`std.process.exit` 不跑调用帧 defer）；**空清单不落盘**（文件缺失即「本次未兑底」）。
5. **日志不写 `docs/消缺台账.md`**。草案 2.2/3.4 设想 logger 回写台账；实际台账为人维护的缺陷档案，程序只写 `logs/untranslated_phrases.json`。
6. **性能（R7）**：fullwidth 检测对 CJK 密集文本的热路已用**首字节位图快跳**（`mayNeedSpecialCheck`）——正常母语词元不含危险/全角/不可见特征首字节时直接扫白名单，不跳逐码点白名单（同形异体仍被拦）。
7. **选包（R9）**：`--lang <名>` 经 `cli.findLangFlag`/`stripLangFlag` 与 `lang/registry.zig` 按名选包，白名单/回译都随所选包生效。
8. **`Config.log_path` 不驱动落盘（第 197 轮 D64）**：该字段在草案里是可配项，但实现中它**零消费者**——实际写入点位由 `main.zig` 的 `flushUntranslated` 决定（`filter` 是 `zigCompile` 帧内局部、进程出口拿不到实例）。现两侧同取模块级单一真值 `pub const default_log_path`（值仍为 `logs/untranslated_phrases.json`，行为零变更），改本字段默认值不再可能与写侧漂移；要让**实例级**配置真生效，须把 filter 或路径提到进程级（同 `machine_mode` 先例），当前无此需求。（第 198 轮 D66 旁注：main 侧已把该真值改作进程级可覆写变量 `untranslated_log_path` 的**默认初值**——生产恒取默认、行为零变更，做成变量只为让测块能把自己的盘上产物改名以免并跑互踩，不改变本节「实例级不生效」结论。）
